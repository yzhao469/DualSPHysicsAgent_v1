## 2.4.1 Domain Limits (Casedef → Geometry → Definition)

*(PDF pages 19–20)*

`dp` defines the distance between particles.
**When changing this parameter, the total number of particles is modified.**

`pointmin` and `pointmax` define the dimensions of the domain where particles can be created.

> **NOTE:** Particles are only created within this domain. Once particles have been created, the dimensions of the domain for simulation are calculated again starting from the minimum and maximum positions of the created particles. The simulation domain can also be configured in `<parameters>`.

```xml
<!--DEFINITION OF DOMAIN WHERE PARTICLES WILL BE CREATED -->
<definition dp="0.005">
  <pointmin x="-0.05" y="0.1" z="-0.05" />
  <pointmax x=" 2.00" y="0.1" z=" 1.00" />
</definition>
```

### 2-D Configuration

A 2-D configuration can be generated by imposing the same values along the Y-direction so that `<pointmin>` y = `<pointmax>` y.

## 2.4.2 Drawing Commands (Casedef → Geometry → Commands)

Several commands in `<mainlist>` are executed by the GenCase program to create the case geometry in SPH particles.

*(PDF page 21)*

```xml
<commands>
  <mainlist>
    <setshapemode>dp | bound</setshapemode>
    <setdrawmode mode="full" />
    <!--CREATION OF FLUID PARTICLES (BOX OF WATER)-->
    <setmkfluid mk="0" />
    <drawbox>
      <boxfill>solid</boxfill>
      <point x="0" y="0" z="0" />
      <size x="0.4" y="0.67" z="0.3" />
    </drawbox>
    <!--CREATION OF BOUNDARY PARTICLES (WALLS OF TANK) -->
    <setmkbound mk="0" />
    <drawbox>
      <boxfill>bottom | left | right | front | back</boxfill>
      <point x="0" y="0" z="0" />
      <size x="1.6" y="0.67" z="0.4" />
    </drawbox>
    <shapeout file="" />
  </mainlist>
</commands>
```

- **Volume of fluid:** `setmkfluid mk=0`, *solid* to create particles within the specified volume; `drawbox` to plot a rectangular box defining a corner and its size in the 3 directions.
- **Boundary Tank:** `setmkbound mk=0`, specify box faces on which particles are created (top is not used in this example).

### Command Lists

*(PDF page 22)*

Mainlist and auxiliary lists of commands:

- Several commands are executed by GenCase to create the geometry in SPH particles.
- Drawing commands are located in the `mainlist` section, but other command lists can be created and called by mainlist or other lists using `<runlist>`.
- Multiple consecutive calls to `<runlist>` can be done using `times="number"`. For example: `<runlist name="StructureList" times="5" />`.

```xml
<geometry>
  <commands>
    <list name="BoxList">
      <drawbox>
        <boxfill>all</boxfill>
        <point x="0" y="0" z="0" />
        <size x="1" y="1" z="0.3" />
      </drawbox>
    </list>
    <list name="CylinderList">
      <drawcylinder radius="0.3">
        <point x="0" y="0" z="0" />
        <point x="0" y="0" z="1.2" />
      </drawcylinder>
    </list>
    <list name="StructureList">
      <matrixsave />
      <runlist name="BoxList" />
      <move x="0.5" y="0.5" z="0.3" />
      <runlist name="CylinderList" />
      <move x="-0.5" y="-0.5" z="1.2" />
      <runlist name="BoxList" />
      <matrixload />
    </list>
    <mainlist>
      <setshapemode>actual | bound</setshapemode>
      <setdrawmode mode="full" />
      <setmkbound mk="0" />
      <runlist name="StructureList" />
      <move x="1.5" y="0" z="0" />
      <setmkbound mk="1" />
      <runlist name="StructureList" />
      <move x="1.5" y="0" z="0" />
      <setmkbound mk="2" />
      <runlist name="StructureList" />
      <shapeout file="" />
    </mainlist>
  </commands>
</geometry>
```

### Drawing Settings

#### setdrawmode

*(PDF page 23)*

`<setdrawmode>` indicates the mode used to create points where particles will be generated:

| Mode     | Description                   |
|----------|-------------------------------|
| `wire`   | Wire mode                     |
| `face`   | Draw faces only               |
| `solid`  | Draw inside (fill solid)      |
| `full`   | Combines face and solid       |

```xml
<mainlist>
  <setdrawmode mode="wire" />
  <setdrawmode mode="face" />
  <setdrawmode mode="solid" />
  <setdrawmode mode="full" />
</mainlist>
```

#### setshapemode — VTK Output

*(PDF pages 24–25)*

`<setshapemode>` defines the draw operations to create VTK files (polygons):

| Token    | Description                                      |
|----------|--------------------------------------------------|
| `actual` | Using the real coordinates                       |
| `dp`     | Adjusting coordinates to dp                      |
| `fluid`  | Operations with mk-fluid                         |
| `bound`  | Operations with mk-bound                         |
| `void`   | Operations with mk-void                          |
| `null`   | Disable the generation of shapes                 |

```xml
<mainlist>
  <setshapemode>actual | bound</setshapemode>
  <setshapemode>actual | bound | fluid</setshapemode>
  <setshapemode>dp | bound</setshapemode>
  <setshapemode>dp | void</setshapemode>
  <setshapemode>actual | dp | void</setshapemode>
  <setshapemode>null</setshapemode>
</mainlist>
```

**shapeout** creates VTK files (polygons) of all the bound objects:

```xml
<mainlist>
  <setshapemode>dp | bound</setshapemode>
  <setdrawmode mode="full" />
  <setmkfluid mk="0" />
  <!--+drawbox ... -->
  <setmkbound mk="0" />
  <!--+drawbox ... -->
  <shapeout file="Box" />
  <setmkvoid />
  <!--+drawbox ... -->
  <setmkbound mk="1" />
  <!--+drawbox ... -->
  <shapeout file="Building" />
</mainlist>
```

Using `reset="true"`, objects created after this command will be saved on a different VTK file:

```xml
<mainlist>
  <setshapemode>actual | dp | bound</setshapemode>
  <setdrawmode mode="full" />
  <setmkfluid mk="0" />
  <!--+drawprism ... -->
  <setmkvoid />
  <!--+drawbox ... -->
  <setdrawmode mode="face" />
  <setmkbound mk="10" />
  <!--+drawbox ... -->
  <setmkbound mk="0" />
  <!--+drawprism mask="96" ... -->
  <shapeout file="" reset="true" />
</mainlist>
```

#### setactive

*(PDF page 26)*

`<setactive>` activates or deactivates the drawing of points (`drawpoints`), the generation of shapes for output VTK using `<shapeout>` (`drawshapes`), and the registration of output VTK files in `<vtkout>` section (`vtkout`). All values are activated by default.

```xml
<!-- Generates shapes for VTK but no points (particles) are drawn. -->
<setactive drawpoints="false" />

<!-- No shapes are generated. Equivalent to <setshapemode>null</setshapemode> -->
<setactive drawshapes="false" />

<!-- Output VTK files created by <shapeout> are not added to the list in <vtkout>. -->
<setactive vtkout="false" />
```

#### resetdraw

`<resetdraw>` resets all options to their default value and deletes all points drawn.

```xml
<resetdraw />
```

### MK Selection

*(PDF page 27)*

These commands indicate the type of particles to be generated:

| Command              | Description                                                         |
|----------------------|---------------------------------------------------------------------|
| `<setmkvoid />`      | Defines the label mk to draw points of type *void* (empty)         |
| `<setmkfluid mk="N" />`  | Defines the label mk to draw points of type *fluid*            |
| `<setmkbound mk="N" />`  | Defines the label mk to draw points of type *bound*            |
| `<setmknextfluid next="true" />`  | Increases (or decreases with `false`) the mk value for fluid |
| `<setmknextbound next="true" />`  | Increases (or decreases with `false`) the mk value for bound |
| `<setmknextauto auto="true" />`   | After each draw command mk is increased automatically         |

```xml
<commands>
  <mainlist>
    <setmkvoid />
    <setmkfluid mk="0" />
    <setmkbound mk="0" />
    <setmknextfluid next="true" />
    <setmknextbound next="false" />
    <setmknextauto auto="true" />
  </mainlist>
</commands>
```

### Transformations

*(PDF pages 28–29)*

Transformation utilities:

| Command          | Description                                                              |
|------------------|--------------------------------------------------------------------------|
| `<move>`         | A displacement is applied to the transformation matrix                   |
| `<scale>`        | Scaling is applied to the matrix                                         |
| `<rotate>`       | A starting vector and angle are given for object rotation                |
| `<rotateline>`   | A starting vector (defined by two points) and angle for object rotation  |
| `<matrixreset>`  | The modified matrix is replaced by the original one (identity matrix)    |
| `<matrixsave>`   | Saves the current transformation matrix in a stack                       |
| `<matrixload>`   | Recovers the last transformation matrix stored in the stack              |

```xml
<mainlist>
  <setshapemode>dp | bound</setshapemode>
  <setmkbound mk="0" />

  <move x="0.5" y="0" z="0" />
  <!--+drawbox ... -->
  <shapeout file="BoxMove" reset="true" />

  <matrixreset />
  <matrixsave />
  <scale x="2" y="1.5" z="0.5" />
  <!--+drawbox ... -->
  <shapeout file="BoxScale" reset="true" />

  <matrixload />
  <rotate ang="45" x="0" y="0" z="1" />
  <rotateline ang="45">
    <point x="0" y="0" z="0" />
    <point x="1" y="1" z="-1" />
  </rotateline>
  <!--+drawbox ... -->
  <shapeout file="BoxRotate" reset="true" />
</mainlist>
```

Example transformation sequence:

```xml
<drawbox ... />
<move x="0.5" y="0" z="0"/>
<drawbox ... />
<scale x="2" y="1.5" z="0.5"/>
<drawbox ... />
<rotate x="0" y="0" z="1" ang="45"/>
<drawbox ... />
```

### Draw Boxes

*(PDF page 35)*

`<drawbox>` draws a box with an initial point and the size. `<boxfill>` indicates if solid or face, and the faces to be hidden.

| boxfill token | Meaning                    |
|---------------|----------------------------|
| `solid`       | Fill the entire box        |
| `all`         | All six faces (hollow)     |

    <boxfill>all^top</boxfill>

#### Mask System

*(PDF pages 40–41)*

`mask` indicates the faces to be hidden. Initially this is defined using **bits**:

| mask value | Binary     | Effect                           |
|------------|------------|----------------------------------|
| `0`        | `0000`     | No faces are hidden              |
| `1`        | `0001`     | First face is hidden             |
| `2`        | `0010`     | Second face is hidden            |
| `4`        | `0100`     | Third face is hidden             |
| `8`        | `1000`     | Fourth face is hidden            |
| `12`       | `1100`     | Third and fourth faces hidden    |

There is a second and easier system to use mask: it can also be defined using the **index of the faces** instead of bits. It is important to use the symbol `|` so the system detects this format.

```xml
<!-- Example: CaseWavemaker — faces 1,2,6,7 are not created; only 3,4,5 -->
<setmkbound mk="0" />
<drawprism mask="1 | 2 | 6 | 7">
  <point x="5" y="0" z="1.5" />
  <point x="5" y="0" z="1.1" />
  <point x="1" y="0" z="0" />
  <point x="0" y="0" z="0" />
  <point x="0" y="0" z="1.5" />
  <point x="5" y="2" z="1.5" />
  <point x="5" y="2" z="1.1" />
  <point x="1" y="2" z="0" />
  <point x="0" y="2" z="0" />
  <point x="0" y="2" z="1.5" />
</drawprism>
```

> Use `"X|X"` if you want to specify only face X (otherwise X will be interpreted as a bit value).

### Redraw Commands

*(PDF pages 52–56)*

GenCase employs a 3-D Cartesian lattice to locate particles. These particles are created at the nodes of that lattice. A value of "mk" is assigned to each node according to the type of particle (boundary, fluid, or void) and to define a special behaviour during the simulation.

| Command            | Description                                                                  |
|--------------------|------------------------------------------------------------------------------|
| `<redraw>`         | Assigns the "mk" defined by the last `<setmkvoid>`, `<setmkbound>`, or `<setmkfluid>` to all nodes that follow a given condition |
| `<redrawnear>`     | Modifies nodes that have a neighbouring node following a given condition     |
| `<redrawbox>`      | Same as `<redraw>` but limits the domain affected                            |
| `<redrawnearbox>`  | Same as `<redrawnear>` but limits the domain affected                        |

```xml
<mainlist>
  <redraw />
  <redraw mkfluid="0" />
  <redraw mkbound="5" />
</mainlist>
```

```xml
<mainlist>
  <redrawnear targettp="fluid" bordertp="bound" />
  <redrawnear times="2" targettp="fluid" bordertp="bound" />
  <redrawnear targettp="void" bordertp="bound" />
  <redrawnear targettp="fluid" targetmk="0" bordertp="bound" />
  <redrawnear targettp="fluid" targetmk="0" bordertp="bound" bordermk="2" />
</mainlist>
```

```xml
<mainlist>
  <redrawbox mkfluid="0">
    <point x="0.1" y="1" z="1.1" />
    <size x="3" y="4" z="2" />
  </redrawbox>
  <redrawnearbox times="3" targettp="void">
    <point x="0.1" y="1" z="1.1" />
    <size x="3" y="4" z="2" />
  </redrawnearbox>
</mainlist>
```

#### Example A

Defines the "mk" for the nodes starting from a specific point, then changes all previous nodes with `mkfluid=1`:

```xml
<setmkbound mk="3" />
<redraw mkfluid="1" />
```

#### Example B

Modifies all nodes of fluid (`targettp="fluid"`) that have a neighbouring node of type boundary (`bordertp="bound"`):

```xml
<setmkbound mk="3" />
<redrawnear targettp="fluid" bordertp="bound" />
```

#### Example C

Modifies all nodes of type void (`targettp="void"`) that have a neighbouring node of type boundary (`bordertp="bound"`) and with `mk=2` (`bordermk="2"`):

```xml
<setmkbound mk="3" />
<redrawnear targettp="void" bordertp="bound" bordermk="2" />
```

#### Practical Example: Closing Holes

*(PDF page 56)*

Redraw commands can be used to close the holes in complex boundary geometries before filling areas with fluid particles.

```xml
<mainlist>
  <setshapemode>real | bound</setshapemode>
  <setdrawmode mode="full" />
  <!-- Creates vertical piston. -->
  <setmkbound mk="0" />
  <drawline>
    <point x="0" y="0" z="2" />
    <point x="0" y="0" z="0" />
  </drawline>
  <!-- Creates bottom from external geometry. -->
  <setmkbound mk="1" />
  <drawfilevtk file="Bottom.vtk" />
  <!-- Fills the holes. -->
  <setmkbound mk="2" />
  <redrawnear times="1" targettp="void"
    bordertp="bound" bordermk="1" />
  <!-- Fills fluid area. -->
  <setmkfluid mk="0" />
  <fillbox x="0.5" y="0" z="0.5">
    <modefill>void</modefill>
    <point x="0" y="-1" z="0" />
    <size x="6" y="2" z="1.5" />
  </fillbox>
</mainlist>
```

### Variables

*(PDF pages 59–65)*

New version of GenCase allows defining variables in the XML. Numerical expressions with these variables are solved by GenCase and DualSPHysics programs.

#### Defining Variables

*(PDF page 59)*

| Command           | Description                                                                 |
|-------------------|-----------------------------------------------------------------------------|
| `<newvar>`        | Creates one or several numerical variables (double precision). Values `true` and `false` are stored as 1 and 0. Variables are created in order so previous variables can be used in following ones. |
| `<newvarstr>`     | Creates one or several text variables.                                       |
| `<newvarcte>`     | Creates numerical variables as constants (cannot be changed).                |
| `<newvarstrcte>`  | Creates text variables as constants (cannot be changed).                     |

The `_rem` attribute is used for comments. The `_print` attribute equal to `true` (or not zero) shows the values stored in the variables on screen.

```xml
<newvar size="0.4" _rem="Defines size" _print="1" />
<newvar var1="10" var2="25.5" var3="var1+var2" var4="true" />
<newvarcte cte1="1.0" cte2="var1+var2/size" cte3="(var1>=cte2)!=var3" />
<newvarstr file1="cube.stl" file2="sphere.stl" />
<newvarstrcte text="The file is [file1]." />
```

#### Predefinition Section

*(PDF page 60)*

The user-defined variables can be defined in section `<predefinition>` and in the drawing command lists. The variables defined in `<predefinition>` can be used to define Dp and the limits of the domain. The user-defined variables are global, so they can only be created once and can be used anywhere.

```xml
<geometry>
  <predefinition>
    <newvarcte sizex="1.2" _rem="size domain"/>
    <newvarcte sizez="sizex*0.8" _rem="size domain"/>
    <newvarcte Dp="sizex/100" _rem="particle size"/>
    <newvarstr filestl="cube.stl"/>
  </predefinition>
  <definition dp="#Dp">
    <pointmin x="#-sizex/2" y="0" z="0"/>
    <pointmax x="#sizex" y="0" z="#sizez"/>
  </definition>
  <commands>
    <list name="DrawShape">
      <newvar posx2="posx1+0.2"/>
      <drawfilestl file="$[filestl]"/>
      <move x="#sizex*posx2" y="0" z="0"/>
    </list>
    <mainlist>
      <newvarcte posx1="-sizex*0.5"/>
      <runlist name="DrawShape"/>
    </mainlist>
  </commands>
</geometry>
```

#### Automatic Constants

*(PDF page 61)*

GenCase creates some variables automatically (as constants) according to values in the XML file, so the user-defined variables can be created from the previous ones. The available constants are:

| Variable(s) | Description |
|---|---|
| `Gravity_x`, `Gravity_y`, `Gravity_z`, `Rhop0` | Gravity values and reference density of the fluid. Loaded at the beginning, before evaluating `<predefinition>` section. |
| `Dp` | Initial inter-particle distance loaded from XML and after evaluating `<predefinition>` section. Dp value can be modified using variables in `<predefinition>`. |
| `PosMin_x`, `PosMin_y`, `PosMin_z`, `PosMax_x`, `PosMax_y`, `PosMax_z` | Domain limits loaded or calculated from XML file. |
| `CaseName` | Name of the case. |
| `Data2D`, `Data2DPosy` | 2D configuration data. |
| `H`, `MassBound`, `MassFluid` | Constant variables calculated automatically starting from previous constants and configuration in XML file. These constants are created before evaluating the drawing command lists. |

#### Modifying Variables

*(PDF page 62)*

The commands `<setvar>` and `<setvarstr>` allow modifying user-defined variables (non-constant). `<setvar>` changes numerical variables and `<setvarstr>` changes text variables. The reference to text or numerical variables must use `[variable]` in text variable definitions.

The command `<printf>` shows the values of text variables, numerical variables, and numerical expressions.

```xml
<newvarcte Cte1="0.1" Cte2="0.2" Cte3="0.3" _rem="Constant values" _print="1" />
<newvar SizeX="0.25" SizeZ="(Dp+2)*2.8" dpd2="Dp/2" _rem="Some variables" />
<setvar SizeZ="SizeX+Cte1*Cte2" _rem="Changes value of SizeZ" _print="true" />
<setvar dpd2="dpd2+Dp" SizeX="SizeX*dpd2" />
<newvarstrcte Text1="Hello" Text2="bye" _rem="Text values" _print="true" />
<newvarstr Text3="AAAA" Text4="[Text1]_[Text2]. SizeX is [SizeX]" _rem="More text values" />
<setvarstr Text3="[Text1]" Text4="BBBB" _rem="Modify values" _print="1" />
```

```xml
<mainlist>
  <newvarstr name="cube" ext=".stl" file="[name][ext]"/>
  <printf text="The file name is $[file]"/>
  <newvar sx="0.25" sz="5.2"/>
  <printf text="Sum of #sx# and #sz# is #sx+sz#"/>
</mainlist>
```

Output:
```
> MAIN
The file name is cube.stl
The sum of 0.25 and 5.2 is 5.45
```

#### Using Variables in Drawing Commands

*(PDF page 63)*

The user-defined variables can be used in most of the drawing commands and the different sections of the XML for GenCase and DualSPHysics programs.

- The use of **numerical variables or expressions** must start with `#` in order to be recognized and evaluated.
- **Numerical or logical expressions** can be used in the `if` attribute recognized by all drawing commands.
- The use of **text variables or expressions** must start with `$` and the name of the variable in square brackets.
- User-defined variables can be used in the following sections of XML: `<geometry>`, `<initials>`, `<floatings>`, `<properties>`, `<motion>`, `<normals>`, `<special>`, and `<parameters>`.

```xml
<mainlist>
  <newvarstr filestl="cube.stl"/>
  <newvar inix="0.2" iniz="0.1"/>
  <move x="#inix" y="0" z="#iniz" />
  <drawbox>
    <boxfill>bottom</boxfill>
    <point x="#PosMin_x" y="0" z="#PosMin_z" />
    <size x="#Dp*20" y="1" z="#Dp*8" />
  </drawbox>
  <drawfilestl file="$[filestl]" if="Dp<=0.1" />
  <runlist name="DrawShape" times="#10/inix" />
</mainlist>

<initials>
  <velocity mkfluid="1" x="0" y="0" z="#-Gravity_z*2"/>
</initials>

<floatings>
  <floating mkbound="2">
    <center x="#inix" y="0" z="#iniz" />
  </floating>
</floatings>
```

#### Expressions and Functions

*(PDF page 64)*

The numerical or logical expressions can use: values, variables, mathematical operators, comparison operators, logical operators, parenthesis, and functions.

| Category | Operators / Functions |
|---|---|
| **Mathematical operators** | `+`, `-`, `*`, `/` |
| **Comparison operators** | `==` (equal), `!=` (not equal), `<`, `>`, `<=`, `>=` |
| **Logical operators** | `!` (not), `\|\|` (or), `@@` (and) |
| **Constants** | `pi()`, `e()` |
| **Casting** | `int(a)`, `float(a)` |
| **Rounding** | `abs(a)`, `floor(a)`, `ceil(a)`, `round(a)`, `fmod(a,b)`, `fmodr(a,b)` = round(fmod(a,b)) |
| **Min / Max** | `min(a,b)`, `min(a,b,c)`, `min(a,b,c,d)`, `max(a,b)`, `max(a,b,c)`, `max(a,b,c,d)` |
| **Power / Log** | `sqrt(a)`, `exp(a)`, `log(a)`, `log10(a)`, `pow(a,b)` |
| **Trigonometric (radians)** | `sin(r)`, `cos(r)`, `tan(r)` |
| **Trigonometric (degrees)** | `sindg(d)`, `cosdg(d)`, `tandg(d)` |
| **Hyperbolic** | `sinh(a)`, `cosh(a)`, `tanh(a)` |
| **Inverse trigonometric** | `asin(a)`, `acos(a)`, `atan(a)` |
| **Random** | `randinit(seed)`, `random()` — initialise the random generator and obtain random numbers |
| **Conditional** | `eval(condition, v1, v2)` — returns `v1` when condition is true, `v2` otherwise |
| **Wave** | `wavelength(gravity, depth, waveperiod)` — returns wave length |

#### Variables in DualSPHysics Program

*(PDF page 65)*

DualSPHysics defines a set of constant variables when execution starts. These variables and the user-defined variables in the `<geometry>` section can be used in the XML sections loaded by DualSPHysics (`<special>` and `<parameters>`).

**List of variables automatically created by DualSPHysics:**
`CaseName`, `Data2D`, `Data2DPosy`, `H`, `B`, `Gamma`, `Rhop0`, `Dp`, `Gravity_x`, `Gravity_y`, `Gravity_z`, `MassFluid`, `MassBound`, `TimeMax`, `TimeOut`.

All user-defined variables in `<geometry>` section are included in `<execution><uservars>` by default. However, the list of variables to use in DualSPHysics can be defined using the command `<exportvar>`.

```xml
<casedef>
  <geometry>
    <mainlist>
      <newvarstr file="box.stl"/>
      <newvar numbers="12"/>
      <newvar sizex="0.25" sizez="5.2"/>
      <newvar sizetot="sizex+sizez"/>
      <newvar num1="0.1" num2="0.2"/>
      <exportvar vars="file,num1,sizez"/>
    </mainlist>
  </geometry>
</casedef>
```

With the `<exportvar>` above, only the specified variables are exported. The resulting `<execution>` section will contain:

```xml
<execution>
  <special/>
  <parameters/>
  <particles/>
  <constants/>
  <uservars>
    <varstr name="file" value="box.stl"/>
    <varnum name="num1" value="0.1"/>
    <varnum name="sizez" value="5.2"/>
  </uservars>
  <motion/>
  <vtkout/>
</execution>
```

Without `<exportvar>`, all user-defined variables are exported:

```xml
<execution>
  <special/>
  <parameters/>
  <particles/>
  <constants/>
  <uservars>
    <varstr name="file" value="box.stl"/>
    <varnum name="num1" value="0.1"/>
    <varnum name="num2" value="0.2"/>
    <varnum name="numbers" value="12"/>
    <varnum name="sizez" value="5.2"/>
  </uservars>
  <motion/>
  <vtkout/>
</execution>
```
